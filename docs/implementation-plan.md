# Icaro — Go Implementation Plan (Milestone: Phases 1–4)

## Context

`docs/blueprint-analysis.md` (on this branch, PR #1) is the spec: a workflow engine where
each step is a Docker container run under hardened defaults, triggered by webhooks/cron/API,
with credentials as first-class "connections", and an MCP server + skill so AI agents can
author workflows against a generated JSON Schema. The repo currently has only the blueprint
and a LICENSE — this plan turns Phases 1–4 of §8 into a Go codebase. Phases 5–6 (SCM
adapters, integration/harness catalog, in-step MCP) are sketched at the end so nothing in
1–4 paints them into a corner.

### Decisions already made

| Topic | Decision |
|---|---|
| Milestone | Phases 1–4: engine core, webhook+cron triggers, connections + `http` step, MCP server + skill |
| Auth | Single-tenant API bearer tokens from day one (`icaro token create`), hashed in DB |
| DB layer | `database/sql`, hand-written portable SQL, `modernc.org/sqlite` (pure Go) + `pgx/v5` stdlib driver, `pressly/goose` migrations per dialect |
| Durability | Runs survive restarts: step state persisted before container start; runner re-attaches to containers by label |
| MCP SDK | Official `github.com/modelcontextprotocol/go-sdk` |
| Expressions | Go `text/template` (`{{ }}`) for interpolation **and** `if:` (renders to `true`/`false`) |
| Logs | Files on disk (`<data>/logs/<run>/<step>.log`), secret-scrubbed on write; DB holds path/size |
| CI | Unit everywhere + integration job with real Docker and a Postgres service (both-backend matrix) |

### Decisions taken in this plan (flag if you disagree)

- Module `github.com/ggrocco/icaro`, Go 1.24, single binary `icaro`.
- CLI: `spf13/cobra`; config: `knadh/koanf` (file `icaro.yaml` + `ICARO_*` env). HTTP: stdlib `net/http` (1.22 method routing) — no framework.
- IDs are ULIDs stored as TEXT (`oklog/ulid`) — portable across both DBs, sortable.
- Connection encryption: `nacl/secretbox` with a 32-byte master key from `ICARO_MASTER_KEY` or `<data>/master.key` (generated by `icaro init`, mode 0600).
- Schema: `invopop/jsonschema` generates; `santhosh-tekuri/jsonschema/v6` validates (gives JSON-pointer paths).
- `http` step runs **in-process** in the runner (no container) with an SSRF guard (deny loopback/link-local/private ranges unless configured).
- `icaro mcp` (stdio) **proxies to the server over the REST API**; `/mcp` (streamable HTTP) runs in-process. Both share one tool-definition layer over a `Backend` interface — one code path for tool semantics.
- Step I/O contract lives on a per-run named volume mounted at `/icaro` (input.json written via `CopyToContainer` before start, output.json read via `CopyFromContainer` after exit). **Spike 0 verifies this against `--read-only`**; fallback is a tiny init container writing into the volume.
- `if:` semantics: the template is rendered with `missingkey=error`, trimmed, parsed with `strconv.ParseBool`; anything else is a validation error at apply time (templates are parsed at validation, not first run).

## Core design (what the code must implement)

### Workflow spec (`internal/workflow/spec.go`) — the schema source

```go
type Workflow struct {
    Name        string            `json:"name" jsonschema:"required,pattern=^[a-z0-9][a-z0-9-]{0,63}$"`
    Description string            `json:"description,omitempty"`
    On          Triggers          `json:"on,omitempty"`
    Steps       []Step            `json:"steps" jsonschema:"required,minItems=1"`
}
type Triggers struct {
    Webhook  *WebhookTrigger   `json:"webhook,omitempty"`   // {secret: "optional"|"required"}
    Schedule []ScheduleTrigger `json:"schedule,omitempty"`  // [{cron: "*/5 * * * *", input: {...}}]
}
type Step struct {
    Name            string            `json:"name" jsonschema:"required"`
    If              string            `json:"if,omitempty"`
    Run             *RunStep          `json:"run,omitempty"`
    HTTP            *HTTPStep         `json:"http,omitempty"`
    Connection      string            `json:"connection,omitempty"`
    Env             map[string]string `json:"env,omitempty"`
    Sandbox         string            `json:"sandbox,omitempty" jsonschema:"enum=standard,enum=strict,default=standard"`
    Network         string            `json:"network,omitempty" jsonschema:"enum=egress,enum=none,default=egress"`
    Timeout         string            `json:"timeout,omitempty"`   // Go duration, default 30m
    Retry           *Retry            `json:"retry,omitempty"`     // {attempts, backoff}
    ContinueOnError bool              `json:"continue_on_error,omitempty"`
}
type RunStep struct {
    Image   string   `json:"image" jsonschema:"required"`
    Script  string   `json:"script,omitempty"`   // written to /icaro/script.sh, run with Shell
    Command []string `json:"command,omitempty"`  // alternative to Script
    Shell   string   `json:"shell,omitempty"`    // default "sh -e"
    WorkDir string   `json:"workdir,omitempty"`  // default /workspace
    Env     map[string]string `json:"env,omitempty"`
    Limits  *Limits  `json:"limits,omitempty"`   // memory, cpus, pids — may only tighten defaults
}
type HTTPStep struct {
    URL string; Method string; Headers map[string]string; Body any; Auth string // "bearer"|"basic" from connection
    ExpectStatus []int
}
```

Exactly-one-of `run`/`http` (later `uses`/`agent`) is enforced in the semantic pass, not the JSON schema — keeps generated schema simple and error messages good. No field anywhere can weaken the sandbox (`privileged`, host mounts, `/var/run`, `/proc`, `/sys` paths are rejected by validation).

**Validation pipeline** (`validate.go`): YAML → generic JSON → schema validate → decode → semantic checks (unique step names; template parse of every string field with `missingkey=error`; template refs `steps.X` only to *earlier* steps; `if:` parses; connection name exists when a store is supplied; cron parses; duration parses; limits only tighten). Output is `[]Issue{Path, Message, Hint}` — the MCP `validate_workflow` returns this verbatim. Add a nearest-match hint (Levenshtein) for unknown step refs/connection names.

**Templating** (`template.go`): data = `{inputs, steps: {name: {outputs, exit_code, status}}, run: {id, workflow, attempt}}`. FuncMap is an allow-list: `json`, `default`, `upper`, `lower`, `trim`, `quote`, `join`, `index`-safe helpers. No `env`, no file, no exec. Interpolation is applied to `run.script`, `run.command[]`, `env`, `http.*`, `retry`-free fields — not to `name`/`image`.

### Storage (`internal/store`)

Tables (identical DDL modulo types per dialect; `TEXT` for JSON, ULID `TEXT` PKs, RFC3339 `TEXT`/`TIMESTAMPTZ` timestamps):

- `workflows(id, name UNIQUE, version INT, status active|disabled, spec_yaml, spec_json, webhook_token, webhook_secret_ct, created_at, updated_at)`
- `workflow_versions(workflow_id, version, spec_yaml, actor, created_at)` — actor = token name (later: run/step id for §5.4 drafts)
- `runs(id, workflow_id, workflow_version, status queued|running|succeeded|failed|cancelled, trigger_kind api|webhook|schedule, input_json, root_run_id, parent_run_id, depth INT, claimed_by, claimed_at, heartbeat_at, started_at, finished_at, error, created_at)`
- `run_steps(run_id, idx, name, status pending|running|succeeded|failed|skipped, attempt, container_id, exit_code, output_json, log_path, log_size, started_at, finished_at, error)`
- `connections(id, name UNIQUE, type, fields_ct BLOB/BYTEA, created_at, updated_at)`
- `api_tokens(id, name UNIQUE, token_hash, scope admin|write|read, created_at, last_used_at, revoked_at)`
- `webhook_deliveries(id, workflow_id, provider, headers_json, body, verified BOOL, verify_error, run_id, received_at)`
- `schedule_state(workflow_id, cron, last_fired_at, next_at)` — rebuilt from spec on apply
- `runner_meta(key, value)` — persistent runner id

Mechanics: SQL written with `?`; `dialect.Rebind` converts to `$N` for Postgres (sqlx-style, ~30 lines). Both engines support `INSERT … ON CONFLICT` and `UPDATE … RETURNING` — use only those shared features. SQLite DSN gets `_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)` and `db.SetMaxOpenConns(1)` (single writer; acceptable for v1, noted as the first Postgres-only relaxation). Migrations via `pressly/goose/v3` with `embed.FS`, dir picked by driver.

Queue claim (portable):
```sql
UPDATE runs SET status='running', claimed_by=?, claimed_at=?, heartbeat_at=?
WHERE id = (SELECT id FROM runs WHERE status='queued' ORDER BY created_at LIMIT 1)
  AND status='queued'
RETURNING id
```

Store tests run against SQLite always and against Postgres when `ICARO_TEST_POSTGRES_DSN` is set (same test functions, table-driven over drivers).

### Runner (`internal/runner`)

- **Loop**: claim → execute → finish; heartbeat every 10s; concurrency from config (default 2); in `--role all` the API notifies the runner via an in-process channel so latency is ~0, otherwise poll every 1s.
- **Executor state machine per run**: `create workspace volume icaro-ws-<run>` + `icaro-io-<run>` → for each step: `if:` → skipped | resolve templates → persist `run_steps` row (running, attempt) → create container (labels `icaro.run`, `icaro.step`, `icaro.attempt`) → persist `container_id` **before** start → copy `input.json` (+ `script.sh`) → start → stream logs to file through scrubber → wait with timeout ctx → `CopyFromContainer /icaro/output.json` (cap 1 MiB; missing = `{}`) → persist → remove container. Failure → retry policy → `continue_on_error` → run status. Volumes removed at run end (config `retention.keep_workspace_on_failure`).
- **Reconcile on startup** (durability): load runs with `claimed_by = my runner id AND status='running'`; for each running step with `container_id`: `inspect` → running ⇒ re-attach (resume logs from `log_size`, wait); exited ⇒ collect outputs, continue; not found ⇒ step failed → retry/fail. Steps without `container_id` restart cleanly (nothing was launched). Single runner id in v1 means stale-heartbeat reclaim is a TODO for multi-runner.
- **Cancel**: API sets `runs.status=cancelled` (if queued) or a `cancel_requested_at`; runner checks between steps and kills the current container.
- **Docker client wrapper** (`runner/docker`): interface with the 8 calls the runner needs (create, start, wait, logs, copyTo, copyFrom, inspect, remove, volume create/remove) — enables the socket-proxy allowlist in §6.1 and a fake for unit tests.

### Sandbox (`internal/runner/sandbox`) — `standard` is the floor

`HostConfig`: `CapDrop: ALL`; `SecurityOpt: [no-new-privileges, seccomp=<embedded profile>]`; `ReadonlyRootfs: true`; `Tmpfs: {/tmp: rw,nosuid,size=256m, /home: rw,nosuid,size=64m, /run: ...}`; `PidsLimit: 256`; `Memory: 1 GiB`, `NanoCPUs: 1`, `Ulimits nofile 4096` (all configurable defaults; steps may only tighten); `NetworkMode: bridge|none`; mounts: only `icaro-ws-<run>` at `/workspace` and `icaro-io-<run>` at `/icaro`. `strict` adds `network: none` unless declared, `PidsLimit 64`, and `Runtime: runsc` when `runner.strict_runtime` is configured. Seccomp: start from moby's default profile JSON, remove `ptrace`, `bpf`, `keyctl`, `mount`/`umount2`, `unshare`, `setns`, `*module` from the allow list; embed with `go:embed`. Secret scrubbing: `logs.ScrubWriter` replaces every connection field value (len ≥ 6) with `***`, line-buffered.

### Connections + injection (`crypto`, `service.Connections`)

Types registry in code for v1: `generic` (any fields), `bearer` (`token`), `basic` (`username`,`password`). Fields JSON sealed with secretbox (random nonce prefixed). Injection: `ICARO_CONN_<UPPERFIELD>` env on `run` steps; `http` step uses the connection for `Authorization` when `auth: bearer|basic`. API/MCP list responses expose `{name, type, field_names}` — never values.

### `http` step (`runner/steps/http.go`)

Templated URL/headers/body → request with 60s timeout, redirects limited to 3 and re-checked by the SSRF guard (resolve host, deny loopback/link-local/RFC1918/ULA unless `http_step.allow_private_networks: true`), response body cap 1 MiB → outputs `{status, headers, body, json}` (`json` populated when content-type is JSON). `expect_status` default 2xx.

### Triggers (`internal/trigger`)

- **Webhook**: `POST /hooks/{workflow}/{token}` (token generated on apply when `on.webhook` present; `icaro workflow get` prints the URL). If `secret: required` (or a secret is set), verify `X-Icaro-Signature: sha256=<hex hmac(body)>`. Body cap 1 MiB; per-endpoint rate limit (`x/time/rate`). Every request → `webhook_deliveries` row (verified or not) → enqueue run with input `{headers: <allow-listed>, body: <parsed JSON or raw string>}`. `POST /api/v1/deliveries/{id}/redeliver`.
- **Scheduler**: `robfig/cron/v3` parser; loop every 30s in the server role: for each `schedule_state` row with `next_at <= now` → enqueue → set `last_fired_at`, recompute `next_at`. Idempotent across restarts (persisted `next_at`); misses during downtime fire once, not N times.

### REST API (`internal/api`) — `/api/v1`, bearer auth, JSON

`GET/POST /workflows`, `GET/PUT/DELETE /workflows/{name}`, `POST /workflows/validate`, `POST /workflows/{name}/runs`, `GET /workflows/{name}/runs`, `GET /runs/{id}`, `GET /runs/{id}/steps/{idx}/logs?tail=N`, `POST /runs/{id}/cancel`, `GET/POST /connections`, `DELETE /connections/{name}`, `GET /deliveries?workflow=`, `POST /deliveries/{id}/redeliver`, `GET /schema/workflow`, `GET /healthz` (unauthenticated). Scopes: `read` (GETs), `write` (+ runs/workflows/validate), `admin` (+ connections, deliveries). Handlers are thin: decode → `service` → encode; errors as `{error, issues[]}`.

### Service layer (`internal/service`)

`Workflows{Apply, Get, List, Delete, Validate}`, `Runs{Enqueue(workflow, input, trigger, parent), Get, List, Cancel, Logs}`, `Connections{Create, List, Delete}`. `Apply` = validate → bump version → write `workflows` + `workflow_versions` → rebuild `schedule_state` → ensure webhook token. This is the only place business rules live; REST and MCP both call it.

### MCP (`internal/mcp`)

Tools: `get_workflow_schema`, `list_workflows`, `get_workflow`, `validate_workflow`, `create_workflow`, `update_workflow`, `run_workflow`, `get_run` (status + per-step outputs + log tail ≤ 200 lines/32 KiB), `list_connections`. Resources: `icaro://schema/workflow`. `Backend` interface implemented by `service` (in-process, for `/mcp` streamable HTTP with the same bearer middleware) and by `apiclient` (for `icaro mcp` stdio). `validate_workflow` returns `Issue[]` as structured content. No delete tools.

**Skill** (`skills/icaro-workflows/SKILL.md`): the §5.3 loop, step-contract cheat sheet, two worked examples, gotchas, and a `.mcp.json` snippet for Claude Code (`{"icaro": {"command": "icaro", "args": ["mcp"]}}`).

### CLI (`internal/cli`)

`icaro init` (data dir, master key, migrate) · `icaro serve [--role all|server|runner]` · `icaro workflow apply|get|list|validate|delete` · `icaro run <name> [--input file|-] [--wait]` · `icaro runs get|list|logs|cancel` · `icaro connection create --type T --field k=v… | list | delete` · `icaro token create|list|revoke` · `icaro mcp` · `icaro schema` · `icaro migrate`. `init`/`token`/`migrate` use the store directly (bootstrap; no chicken-and-egg with auth); everything else goes through `apiclient` using `server.url` + `token` from config/env.

## Implementation order (each item ends green with tests)

**Spike 0 — de-risk the container I/O contract (½ day)**
Throwaway program: create container with `--read-only` + tmpfs + `/icaro` named volume, `CopyToContainer` `input.json` before start, run `sh -c 'cat /icaro/input.json; echo {\"ok\":true} > /icaro/output.json'`, `CopyFromContainer` result, with `CapDrop ALL` + `no-new-privileges` + embedded seccomp. Confirms the §2.1 contract under §6.1 defaults. Fallback if copy-into-volume fails: `alpine` init container writing the file.

**Phase 1 — Engine core**
1. Scaffold: `go mod init`, cobra root, koanf config with defaults, `Makefile` (build/test/lint/generate), `.github/workflows/ci.yml` (lint, unit, integration job with Docker + `postgres:16` service), `Dockerfile` (distroless static), `docker-compose.yml` (rootless-friendly notes).
2. `internal/workflow`: spec types, `go generate` → `schema/workflow.schema.json`, drift test, validator + semantic pass, templating with restricted FuncMap; golden tests in `testdata/` (valid/invalid YAMLs with expected `Issue` paths).
3. `internal/store`: dialect + rebind, migrations `0001_init` for both dialects, repos, queue claim, driver-matrix tests.
4. `internal/crypto` + `api_tokens` + `icaro init` / `icaro token`.
5. `internal/runner/docker` wrapper + fake; `sandbox` builders + embedded seccomp; `logs` scrubbing writer + file store.
6. `internal/runner`: executor for `run` steps, retry, timeout, cancel, reconcile-on-start; integration tests against real Docker (`alpine`): happy path, non-zero exit, timeout kill, output cap, reconcile after simulated restart (kill runner mid-step, restart, assert completion).
7. `internal/service` + `internal/api` (workflows, runs, logs, schema, healthz) + `apiclient` + CLI `serve/workflow/run/runs/schema`. `examples/hello.yaml`.

**Phase 2 — Triggers**
8. Webhook gateway: token/secret on apply, HMAC verify, delivery records, rate limit, enqueue, redeliver endpoint, `examples/webhook-echo.yaml`. Tests: valid/invalid signature, oversize body, redelivery.
9. Scheduler: `schedule_state` rebuild on apply, loop, restart idempotency test with a fake clock.

**Phase 3 — Connections + `http` step**
10. Connection types registry, sealed storage, CLI/API, env injection into `run` steps, scrubber wired to connection values.
11. `http` step executor with SSRF guard and outputs; `examples/http-step.yaml`; tests with `httptest` server + guard table tests.

**Phase 4 — MCP + skill**
12. `internal/mcp`: tool/resource definitions over `Backend`; in-process `/mcp` route with auth; `icaro mcp` stdio over `apiclient`. Tests: tool round-trips via the SDK's in-memory transport; `validate_workflow` returns structured issues.
13. `skills/icaro-workflows/SKILL.md` + examples + `.mcp.json` snippet; README quick start.

## Forward-compatibility hooks for Phases 5–6 (do now, cheap)

- `runs.root_run_id/parent_run_id/depth` and `workflow_versions.actor` exist from migration 0001 (§5.4 lineage + draft authorship).
- `workflows.status` includes `draft` in the enum even if unused until §5.4.
- Trigger adapter interface stub in `internal/trigger/adapter.go` (`Verify`, `Normalize`) with the generic webhook implemented through it — GitHub/GitLab adapters slot in without touching the gateway.
- `Step` struct reserves `Uses string` and `Agent *AgentStep` fields tagged `jsonschema:"-"` until Phase 6 (so the semantic exactly-one-of check already knows about them).
- `runner/docker` interface is the exact allowlist to configure a docker-socket-proxy later.

## Verification (end-to-end, after Phase 4)

1. `make lint test` (unit) and `make test-integration` locally with Docker running; CI green on the SQLite and Postgres matrix.
2. `icaro init && icaro token create --name dev --scope admin` → export token; `icaro serve` in another terminal.
3. `icaro workflow apply examples/hello.yaml && icaro run hello --input '{"who":"icaro"}' --wait` → run `succeeded`, `icaro runs logs <id> 0` shows output, `icaro runs get <id>` shows `outputs`. Confirm with `docker inspect` during the run: `CapDrop=[ALL]`, `ReadonlyRootfs=true`, `SecurityOpt` contains `no-new-privileges` and the seccomp profile, no host mounts.
4. Durability: start a step that sleeps 60s, `kill -9` the `icaro serve` process, restart → run completes `succeeded` and the log file continues without gaps.
5. Webhook: `icaro workflow apply examples/webhook-echo.yaml`, `curl -X POST <printed URL> -d '{"a":1}'` with and without a valid `X-Icaro-Signature` → one run enqueued, one 401 delivery recorded; `POST /deliveries/{id}/redeliver` creates a second run.
6. Schedule: workflow with `cron: "* * * * *"` fires once per minute; restart the server across a minute boundary → exactly one run for that minute.
7. Connections + http: `icaro connection create httpbin --type bearer --field token=abc`; `examples/http-step.yaml` posts to an `httptest`-style local echo (or httpbin) and the run's outputs show the `Authorization` header arrived; the token value never appears in logs (`grep` the log file); a step targeting `http://169.254.169.254` fails with the SSRF guard error.
8. MCP: add `.mcp.json` with `icaro mcp` to a Claude Code project, ask it to "create a workflow that …" using the skill; observe it calling `get_workflow_schema` → `validate_workflow` (feed a deliberate typo like `imgae:` and confirm the issue path `/steps/0/run/imgae` and hint) → `create_workflow` → `run_workflow` → `get_run`. Repeat through `/mcp` over HTTP with the bearer token.
